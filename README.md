## Currently building

<a href="https://github.com/Samudra-GITHub/Samagra-OS"><img src="./assets/profile/samagra-os.svg" width="100%" alt="Samagra OS: an animated kernel view with an address-space map, privilege rings with system calls and a timer interrupt, and a round-robin scheduler. Boot, memory, interrupts and scheduler are implemented; user mode and a RAM-only filesystem are early; heap, networking, persistent storage and a native desktop are planned." /></a>

A real x86-64 operating system, built from first principles. It boots into long mode, manages physical and virtual memory, handles CPU exceptions and hardware interrupts, and runs a preemptive scheduler over kernel tasks. Early user-mode support has started: Ring 3, per-process address spaces, a small system-call interface and a non-persistent RAM filesystem. Persistent storage, networking and a native desktop are still to come.<br>
<sub>C · x86-64 assembly · Clang / LLD / NASM · QEMU &nbsp;·&nbsp; [GitHub ↗](https://github.com/Samudra-GITHub/Samagra-OS)</sub>

## Engineering with AI

<img src="./assets/profile/ai-workflow.svg" width="100%" alt="Left-to-right workflow. Samudra, a human, provides direction and validation. Direction flows to two AI engineering agents: Claude Code for UI, docs and design, and Antigravity for kernel, memory and scheduling. Both work in one shared repository with sync logs, handoff notes, docs, API contracts and commits. Validation flows back to Samudra through review, run, and accept or reject." />

Claude Code and Antigravity are AI engineering agents, not people. I use them as part of my workflow, not as a replacement for engineering decisions: I set architecture, direction and validation, and they implement. They coordinate through the repository itself: shared docs, interface contracts, handoff notes and commits.
